How to use the API

Encryption

Accounts are encrypted. If a user downloaded his key and removed it from the server, you should provide a way to let him insert the key. Using the API, just add "enckey" to the body to include a custom encryption key.

Sign In/Sign Up

The sign in and sign up processes are managed by the API, and they both return a generic token that gives basic access to the account.
This token is required for all the actions on the account, but alone it can just retrieve basic info such as name, surname and some other little details.

What do you need to provide in the sign-in/sign-up pages? Simple, only a GET redirect parameter, leading to the page that requested the access.

Validating a token

Validating tokens is really easy, you just need to execute a POST fetch request:

fetch('/api/restoresession', {method: 'POST', body: JSON.stringify({
response: 1, //* Gives response instead of redirecting
token: "Token to validate"
})}).then(r=>r.text()).then(async r=>{
//* Do whatever with response ("NOT" if invalid, TOKEN otherwise)
});

Connecting an App

This is a more delicate step, but the most important of all: Linking/Connecting an app to your account.
As the sign in/up operation, this also returns a simple token ( apptoken ), but this time it's a specific token for the connected app (it's reccomended to save it somewhere for further usage). This token allows you to actually manage the data of your and other apps you requested access to.

What parameters do you need to provide when linking an app? This time, a bunch more of them:

"redirect" (the target page)
"link-token" (the account token)
"apptoken" (the app's ID)
"appscope" (the app's name)
"appauthor" (the app's author)
OPTIONALS ---
"appicon" (In base64 format)
"app-permissions" (JSON, list of permissions and accessible folders)
"link-permissions" (JSON, permissions over other apps)

You can redirect from an app like this:

location.href = '/auth/link?' + new URLSearchParams({
"redirect": location.pathname, //* Returns a GET variable "apptoken"
"link-token": "Generic Account Token",
"apptoken": "This app's token / ID",
"appscope": "This app's name",
"appauthor": "This app's author",
//* OPTIONAL ELEMENTS HERE
"appicon": "This app's base64 icon",
"app-permissions": JSON.stringify({"Permission Name": ["/folder/", "/fileOrFolder", "/file.txt"]}), //* Available app permissions. Every app with specific permission will have access to all files/folders that begin with given path.
"link-permissions": JSON.stringify({"Another app's token / ID": ["Permission Name"]}) //* Permissions over other apps.
});

How do permissions work? That's simple, in app-permissions, you define a permission name and the accessible files/folders with it ( {"root": [""], "friends": ["/friends"], "settings": ["/settings/public/", "/settings/general/"]} ).
CAREFUL! "/friends" means the app will have access to "/friends*", for example "/friends/...", "/friends.txt", and so on
Instead, in link-permissions you can insert permissions over other apps ( {"App 2's ID": ["friends", "settings"]} ). This will give the app read, write and move permissions on the allowed folders; Deleting data is NOT possible.

PS: To update an app's info or permissions, just link it again!

Managing data

All data managements are done using fetch POST requests. You are required to provide both the account token and the specific app token, togheter with other app info such as the name, author, and ID.

To write data to another app, you just insert a parameter in front of the file name: %EXECTOAPP:<The other App's ID>%/someFile.txt
REMEMBER: You can NOT use this parameter if you don't have the required permissions, or when deleting files (to prevent unexpected data losses).

Managing data

Writing, reading, moving and deleting data is all done with the same pattern. You can format the file name with any path you'd like (../ will be automatically removed from all requests!); Here's the format:

fetch('/api/data/<action>', {method: 'POST', body: JSON.stringify({
token: "Generic Account Token",
app: {
name: "This app's name",
author: "This app's author",
id: "This app's token / ID",
token: "App Account Token (from linking app)"
},
data: {
name: "File Name (source file when moving)",
content: "File Content (target file when moving)" //* (Omit when deleting or reading)
}
})}).then(r=>r.text()).then(r=>{
//* Do whatever with response: "ERROR: <error>" OR "OK"
});

Valid actions are write, read, move, remove and list. You can use the MOVE action to rename a file; LIST returns a stringified array with directory contents.

Miscellaneous

There are a bunch of other actions you can do with the API

Check if app is linked

If you want to check if another app is linked to an account, maybe before trying to integrate it with yours, you can do it like this:

fetch('/api/misc/isLinked', {method: 'POST', body: JSON.stringify({
token: "Generic Account Token",
app: "App Token / ID",
hasPerms: {...}, //* Optional, permissions of the app over other apps
availablePerms: {...} //* Optional, permissions available in the app
})}).then(r=>r.text()).then(r=>{
//* Do whatever with response ("TRUE", "FALSE" OR eventual error)
//! If hasPerms or availablePerms is defined, and the permissions are different, "DIFFERS" will be returned.
});

This way, you can always check if a user has got all the required permissions

Getting account/app icon

If you need to get an user or an app's icon (if it's present), you can do so like this:

fetch('/api/misc/geticon', {method: 'POST', body: JSON.stringify({
token: "Generic Account Token",
app: "App Token / ID", //* Optional, used to get an app's icon instead
})}).then(r=>r.text()).then(r=>{
//* Do whatever with response (app/account icon in base64, OR eventual error)
});

Updating the app's icon

REMEMBER: It IS required for you to insert an image in base64 format. Other file types are not supported yet.

fetch('/api/data/addicon', {method: 'POST', body: JSON.stringify({
token: "Generic Account Token",
app: { //* Only if adding app icon instead of profile picture
name: "This app's name",
author: "This app's author",
id: "This app's token / ID",
token: "App Account Token (from linking app)"
},
data: {
content: "Base64 Profile Picture / icon"
}
})}).then(r=>r.text()).then(r=>{
//* Do whatever with response: "ERROR: " OR "OK"
});

Get app name from token

If you need for any reason to get an app's name, you can do it like this:

fetch('/api/misc/appname', {method: 'POST', body: JSON.stringify({
token: "Generic Account Token",
app: "App Token / ID"
})}).then(r=>r.text()).then(r=>{
//* Do whatever with response (app name OR eventual error)
});

Validate an encryption key

When trying to read or write data, the API needs to have a valid encryption key existing, either on the account, or on the request as `enckey`. To check if the said key is valid, you can use this API:

fetch('/api/misc/validenckey', {method: 'POST', body: JSON.stringify({
token: "Generic Account Token",
key: "Encryption Key" //* To verify a custom key instead of the default one.
})}).then(r=>r.text()).then(r=>{
//* Do whatever with response (OK / Eventual Error)
});

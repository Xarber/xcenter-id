# Integrate X-Center ID

Register the relying-party app from the X-Center ID developer portal at https://id.xcenter.it/developer. The maintained contract is in [Identity](IDENTITY.md), and the public component and server packages are in the [standalone X-Center ID SDK](https://github.com/Xarber/xcenter-id-sdk).

For a confidential backend authorization flow, register the backend's exact HTTPS callback as a web app. Keep the one-time client secret on that backend. For a public native authorization flow, choose Native app and register the product's OS-verified HTTPS app callback. Native registrations receive a client ID with no client secret. Each app must have its own registration and callback ownership. Publish the portal's TXT challenge at `_xcenter-id.<callback-host>` and activate the pending registration. Pending, restricted, revoked and unknown dynamic clients are unavailable for sign-in.

The Expo package exposes AccountOverview, AccountEntry, RegisteredAppSignIn and authorizeNative. It supplies the account entry UI and a system-browser authorization flow with PKCE, state and nonce. Use `createExpoOAuth` for SDK-managed native code exchange, ID token verification and token renewal. The host app remains responsible for its own account session, secure storage and recovery. The [SDK configuration and sign-in guide](https://github.com/Xarber/xcenter-id-sdk/blob/main/docs/CONFIGURATION.md) covers explicit settings, environment variables and `xid.json` for public clients and backend services. Native access tokens are opaque. Pairwise issuer subjects differ between apps. Account-manager session endpoints are reserved for the account manager.

A backend must retain the login transaction before opening authorization, validate the token audience and stored nonce, and map users by issuer and subject. A client-supplied nonce at completion does not prove that the backend initiated the flow. Public native clients additionally depend on the actual app's verified Universal Links or Android App Links. A copied client ID or matching display name does not establish that ownership.

The installed **Integrate X-Center ID** skill and its repository source under `skills/integrate-xcenter-id` describe portal setup and the host integration decisions. An independent review verified that the instructions reject copied client identities and unsafe backend completion. Browser QA verified that app B cannot redeem app A's authorization code, a code cannot be reused, and an admin restriction makes a registered app unavailable. Actual OS callback ownership still requires testing the installed app.


The public developer documentation route is `/docs`. Install Expo from the standalone SDK source checkout or pack `./packages/expo` from that checkout. SwiftUI, Kotlin/Compose, Flutter and the HTML Web Component ship in the same SDK alongside a Next.js/Vercel adapter. `authorizeNative` and RegisteredAppSignIn accept supported `scopes`, a transaction `nonce` and `promptConsent` for incremental access. Existing defaults remain openid-only. Backend-based apps must create and retain their transaction and nonce before authorizing. The hosted API contract and its backend-key boundary are in [HOSTED_DATA.md](HOSTED_DATA.md).

The integration skill supports non-Expo projects through the [manual OpenID Connect guide](https://id.xcenter.it/docs#manual). Use a library for your platform and choose a backend-owned confidential flow or a public native flow with a verified HTTPS callback. Expo is an optional adapter. Developers can delete pending and active registrations in the portal. Deletion revokes that registration and hides it from the inventory while retaining stored records and its identity tombstone.

Request `files_read`, `files_write`, or `shared_files_read` only if issuer discovery advertises the scope and the product needs it. Use the [delegated Files contract](FRIENDS.md#file-permissions-for-registered-apps) for route and revocation behavior. Keep those permissions separate from private app sync. Cross-app requests appear under the linked source app. The user must first link that source to grant access.
